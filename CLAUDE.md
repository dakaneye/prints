# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A collection of small, self-contained 3D printing projects for a Bambu Lab A1.
Each project under `projects/<name>/` is one of three shapes:

- Pure download — a community STL (MakerWorld/Printables/Thingiverse) with
  only provenance tracked here
- Pure parametric — build123d Python scripts that generate STLs
- Hybrid — a downloaded figurine plus a custom accent part (e.g., engraved
  display base) coded in build123d

The Python in this repo is CAD scripts that emit STLs — not an application.

## Canonical sources

Read these two files first; they're the source of truth for anything
structural:

- `conventions.md` — folder layout, naming, filament catalog, build123d
  script three-section convention (Parameters / Geometry / Export), IP
  posture
- `docs/3d-printing-setup.md` — hardware, slicer workflow, Python/venv
  setup, CI wiring

## Python version — this is the trap

build123d `>=0.10.0` requires Python `>=3.10,<3.14`. Homebrew's default
`python3` on this Mac is 3.14, which pip will refuse. **Always invoke
`python3.13` explicitly** when creating venvs. `pyproject.toml` declares
`requires-python = ">=3.11,<3.14"` to enforce this.

## Two separate venvs

Deliberate, not a mistake:

- **Repo root `.venv/`** — `build123d + pytest`, used to run the test
  suite. Create with `python3.13 -m venv .venv && .venv/bin/pip install -e ".[dev]"`.
- **Per-project `projects/<project>/3d/.venv/`** — just `build123d`, used
  to author/regenerate that project's parts. Create via the steps in
  `docs/3d-printing-setup.md`.

Both are gitignored. The per-project venv is ~500 MB of cached OpenCascade
CAD geometry — rebuild locally on demand, never commit.

## Common commands

```bash
# From repo root — run all smoke tests (runs each generator, asserts valid STL)
.venv/bin/pytest

# Run a single test
.venv/bin/pytest tests/test_wizard_figurine_base.py::test_script_produces_valid_stl

# Lint (matches CI)
ruff check .
ruff format --check .

# Regenerate one part's STL
projects/<project>/3d/.venv/bin/python projects/<project>/3d/<script>.py

# Regenerate every part in a project
projects/<project>/3d/.venv/bin/python projects/<project>/3d/build_all.py
```

Each generator writes to its own `projects/<project>/3d/out/<script_name>.stl`.
`out/` and `*.stl` are gitignored.

## CI is an external reusable workflow

`.github/workflows/ci.yml`, `codeql.yml`, and `scan.yml` all call reusable
workflows from `dakaneye/hookshot`. These files are **generated by the
`~/dev/personal/.github` sync engine** — hand-edits get overwritten on the
next sync. If CI behavior needs to change, change it in hookshot or in the
.github sync repo, not here.

The Python CI workflow installs via `pip install -e ".[dev]"` and runs
ruff + pytest against what's in `pyproject.toml`.

## Tests are smoke tests over generators

`tests/` contains subprocess-style tests that run each project's
generator (`base.py`, etc.) and assert the output STL is non-trivial
(file exists, reasonable size). This catches build123d API drift, import
breakage, and broken boolean ops (empty STL) — it does **not** validate
geometric correctness. When adding a new parametric part, add a
corresponding smoke test to `tests/`.

## build123d script convention

Every `*.py` under any `3d/` directory follows three sections in order:
Parameters (all dimensions in mm, source in comments) → Geometry → Export
(writes to sibling `out/` directory). Full template + naming rules live in
`conventions.md`. Stick to it — the tests, `build_all.py`, and the
slicer-import flow all depend on the `out/<script_name>.stl` output path.

## IP / license boundary — don't cross it

- `projects/*/downloaded/` is globally gitignored. **Never commit
  third-party STL/3MF bytes** — provenance lives in
  `projects/<project>/downloaded/SOURCES.md` (URL + author + license +
  date), the bytes stay local only.
- Public-facing strings (README, folder names, commit messages, PR/issue
  titles) stay IP-neutral — use generic descriptors like "wizard
  figurine," not copyrighted character names. Internal design docs under
  `docs/superpowers/specs/` and per-project `print-log.md` can name
  characters freely; those are design history, not a public site.

## Filament

Only SUNLU PLA+ 2.0 filaments (black, white, grey, oak wood) are on hand
— see `conventions.md` for the catalog. The spools have no RFID, so in
Bambu Studio the filament profile **must be selected manually** ("SUNLU
PLA+ 2.0"). Bambu Studio's `File → Open Project` only accepts `.3mf`
bundles; use `File → Import → Import 3MF/STL` (or drag-drop) for raw STLs.
